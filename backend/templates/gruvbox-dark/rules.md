# Gruvbox 暗 · 质量规则（生成阶段注入）

本文件是这份模板的专属质量规则，与 layouts.md 的版式锁配合使用。

## 字体与语言

- 全局等宽（h1/h2 与正文已内建 JetBrains Mono + Maple CJK 栈）：标题像命令，正文像终端输出，编号与代码天然对齐。不要引入无衬线粗标题去做「现代科技感」。
- 语气要有终端的老练与幽默：写动作、键位、行数与翻牌率（像"这行配置，最近三十天真的用到过吗"），不写抽象大词。
- 数字与英文等宽呈现（模板已内建），不要给数字换字体。

## 结构纪律（琥珀是身份）

- 琥珀橙只允许出现在四处：提示符块/状态栏（gd-prompt / gd-status）、关键数字 gd-stat-v、强调药丸 gd-pill-accent、按钮 gd-btn。禁把琥珀用于大标题、整卡底色或大面积色块。
- 沙黄只管编号与时间点（gd-n / gd-tl-t），苔绿只管语言标签 gd-lang 与环境辉光；三色分工不互换。
- 卡只有一种：暖褐半透明 + 暖棕细描边、小圆角（gd-card）。禁纯白死底、禁大圆角玻璃卡、禁硬阴影（环境辉光与数字辉光是唯一允许的光）。
- 终端窗口 gd-term 只在 code 版式出现，一份 deck 至多 1-2 页；代码 6-10 行、行长 ≤56 字符。

## 禁令

- 禁 emoji；禁高饱和蓝紫、金属渐变、玻璃拟态、现代 IDE 截图拼贴。
- 禁 AI 腔（口号式动词、营销形容词一律换成具体的键位、行数与人话）。
- 禁编造精确数字：数据必须给口径与来源（写在页尾），没有来源就写区间或量级。
- 禁一页多个破折号「——」；引文出处行允许一个。
- 禁高密度表格与密集日志堆叠；对比类内容用 split 或 keynotes 的三卡承载。

## 密度

- 每页可见文字 90-220 字；低于下限会被写入门禁直接拒收。
- 卡片说明 22-44 字：一句论断 + 一句展开，句号结尾的完整句。
- **每页要有下半区**：量测会检查填充率，内容只占画布一半不到的页会被打回；页码页脚（deck-footer）每页都保留。
- **数字纪律**：关键数据一律 metrics 或 moments 呈现，不准埋进句子里。

## 节奏

- 建议顺序：cover → contents → divider → keynotes / split → code → metrics / moments → quote → closing。
- 同一版式最多连用 2 页；quote 全份 deck 出现 1 次，它是收束前的「一行注释」。
- divider 在 8 页以上的 deck 至少出现 1 次；数据页与内容页穿插，不要连排；code 版式全份 1-2 页。
