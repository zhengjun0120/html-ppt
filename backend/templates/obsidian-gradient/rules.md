# obsidian-gradient · 质量规则（生成阶段注入）

本文件是这份模板的专属质量规则，与 layouts.md 的版式锁配合使用。

## 字体与语言

- 中文正文默认字体（Inter + Noto Sans SC），代码/配置/键名/命令用 `.oc-code`（JetBrains Mono）承载，行内代码名词写 `<b style="color:var(--oc-accent3)">`。
- 眉标（`oc-tag`）惯用大写英文标签 + `●` 前缀（如 `● CHAPTER 01`、`● SETUP · 4 STEPS`），气质对齐 GitHub Changelog。
- 渐变字 `oc-g` 是模板记忆点也是滥用重灾区：一页最多 1-2 处，只包 2-6 字短语（一个词），整句渐变 = 没有强调。

## 代码纪律（oc-code）

- config 版式 8-18 行、每行 ≤70 字符；JSON/YAML/命令都必须真实可粘贴，密钥一律打码（`"xxxxxxxx"`）。
- 着色只用登记的类：`cm`（注释）`cc`（键）`cs`（字符串值）`ca`（强调键）`cp`（成功/命令）。不要发明其他着色类。
- HTML 转义：代码里的 `<`、`>`、`&` 必须写成 `&lt;` `&gt;` `&amp;`。

## 数据纪律

- metrics 的大数字必须有口径或时间范围（"90 天"、"n=48"），没有来源就写"估算"或量级；不准编精确数。
- 步骤（steps）编号连续、每步一个动作；命令类内容放 config 版式，不要塞进步骤说明里。

## 禁令

- 禁 emoji（demo 源页的 🧠⚡🔗 属历史样式，新页面一律不用）：胶囊用文字表达。
- 禁在页面里写死颜色：颜色只来自主题 token（`var(--oc-accent)` 等）。唯一例外是 layouts.md 骨架里已写明的 style。
- 禁整页塞 5 步以上流程：超过 5 步拆两页或收敛成 4 步。
- 禁连续 3 页同版式：compare / steps / config 穿插使用，节奏校验会打回。

## 密度

- 每页可见文字 90-200 字（config 代码页另计，代码 8-18 行）；低于下限会被写入门禁直接拒收。
- 卡片要点 10-22 字/条、hl 洞察 25-45 字：一句论断 + 一句展开，句号结尾的完整句，不写半截句。
- **每页要有下半区**：量测会检查填充率，内容只占画布一半不到的页会被打回。
- **数字纪律**：关键数字一律 metrics 大数字卡呈现，不准埋进句子里。

## 节奏

- section（章节幕）至少在 10 页以上的 deck 出现 1 次；
- 教程骨架 cover → section → compare → steps → config → metrics → quote-cta → thanks 保持完整，中间可扩展内容页；
- config（代码页）与 metrics（数据页）穿插在叙事页之间，不要连排。
