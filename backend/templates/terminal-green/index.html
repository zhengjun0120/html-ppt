设计原则

三条不妥协

零依赖

只用标准库

依赖树越短，二进制越可信。行云连日志库都没引，error 自带上下文就够了。

说人话

报错带建议

每个 error 后面跟一句怎么修。用户不该为了一个参数去翻源码或 issue 区。

单文件

一次交付

go build 出一个二进制，scp 到服务器就能跑，不装运行时、不写全局配置。

三层合并

flag 不是唯一入口

配置的读取顺序是：配置文件给默认值，环境变量适配 CI，命令行 flag 最后生效。越靠后的来源优先级越高，用户的心智模型也最简单。

冲突不报错，只在 --verbose 里打印采用了哪一层——安静，但可解释。

-c 并发数 -o 输出目录
01

读配置文件取默认值，路径遵循 XDG 规范

02

环境变量 XINGYUN_ 前缀覆盖配置，适配流水线

03

命令行 flag 最后生效，冲突时打印采用来源

三层合并的入口

internal/options.goGo
func ParseArgs(args []string) (*Options, error) {
    opts := &Options{Concurrency: 4}
    fs := flag.NewFlagSet("xingyun", flag.ExitOnError)
    fs.IntVar(&opts.Concurrency, "c", 4, "并发数")
    fs.StringVar(&opts.Output, "o", "out/", "输出目录")
    fs.BoolVar(&opts.Verbose, "v", false, "详细日志")
    if err := fs.Parse(args); err != nil {
        return nil, err
    }
    return opts, nil
}

flag 只负责最后一步：环境变量与配置文件在进入这个函数之前已经合并完毕。
