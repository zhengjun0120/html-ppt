# tech-sharing · 质量规则（生成阶段注入）

本文件是这份模板的专属质量规则，与 layouts.md 的版式锁配合使用。

## 字体与语言

- 中文正文默认字体即可，不要给中文文本指定衬线或手写字体。
- 代码、命令、文件名、路径、HTTP 状态码、数字指标：一律 `<span class="mono">`。
- kicker 惯用小写技术风格（如 `// context`、`deep-dive · 1 / 2`、`agenda.toml`），与终端审美一致。

## 代码块纪律（terminal）

- `<pre>` 内代码：split-terminal 版式 ≤16 行，code-terminal 版式 ≤22 行；每行 ≤70 字符。
- 语法着色只用登记的五个类：`kw`（关键字）`fn`（函数/类型）`str`（字符串）`cmt`（注释）`num`（数字）。不要发明其他着色类。
- 代码必须真实可读——放伪代码不如不放；写不确定的 API 不如写概念。
- HTML 转义：代码里的 `<`、`>`、`&` 必须写成 `&lt;` `&gt;` `&amp;`。

## 禁令

- 禁 emoji（包括 ✅❌😤✦）：结论用文字 tag 表达（"不现实"、"推荐"、"成本高"）。
- 禁在页面里写死颜色：颜色只来自主题 token（`var(--accent)` 等）。唯一例外是 layouts.md 骨架里已写明的 style。
- 禁编造精确数字：没有来源就用量级（"十万级"、"毫秒级"）或区间。
- 禁每一页都用 cards-3：三卡是主力不是万能，连续 3 页同版式会被节奏校验打回。

## 密度

- 每页可见文字 100-220 字（代码页另计，代码 10-22 行）；低于下限会被写入门禁直接拒收。
- 卡片说明 22-45 字：一句论断 + 一句展开，句号结尾的完整句，不写半截句。
- **每页要有下半区**：量测会检查填充率，内容只占画布一半不到的页会被打回。
- **数字纪律**：关键数字/对比一律 stat-hero、kpi-grid、two-column 呈现，不准埋进句子里。

## 节奏

- 章节幕（section-divider）至少在 10 页以上的 deck 出现 1 次；
- 数据页（stat-hero / kpi-grid）与代码页（split-terminal / code-terminal)穿插在内容页之间，不要连排；
- cover → agenda → …内容… → takeaways → qa 的骨架顺序保持完整。
