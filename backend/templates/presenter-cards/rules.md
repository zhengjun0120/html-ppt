# presenter-cards · 质量规则（生成阶段注入）

本文件是这份模板的专属质量规则，与 layouts.md 的版式锁配合使用。

## 逐字稿纪律（本模板的核心交付物）

- 每页 `<div class="notes">` 写 150-300 字口语逐字稿：少于 150 字提示不够，多于 300 字来不及看。
- 逐字稿不是讲稿，是提示信号——核心点加粗、过渡句单独成段、数据和专有名词列清楚。
- 用口语写：「因此」→「所以」，「该方案」→「这个方案」；写完读一遍，不拗口才对。
- 只给演讲者看的话（提词、衔接句）一律进 notes，页面本体只放给观众看的内容。

## 字体与语言

- 中文正文默认字体；代码、命令、文件名、按键、话题标签用 `<span class="mono">`。
- kicker 惯用小写技术风格（`// part 01 · problem`、`agenda`），与深色 GitHub 审美一致。
- 页面内关键词高亮用 `<span class="accent">` 或 `<strong>`，不要自己上色。

## 组件纪律

- cards-3 的说明是「一句论断 + 一句展开」，22-45 字，句号结尾；不写半截句。
- feature-grid 恰好 4 条、两列各 2 条；序号修饰类按 blue / green / orange / purple 轮转，不要一色到底。
- rule-list 的编号写 01/02/03，标题里最多一个 accent 关键词。
- code-block 只用登记的三个着色类：`comment`（灰注释）`cmd`（绿命令）`flag`（橙按键/旗标）；代码 6-14 行、每行 ≤60 字符，`<` `>` `&` 必须转义。

## 禁令

- 禁 emoji（✅❌💡✦）：结论用文字表达（"推荐"、"成本高"、"差别在哪"）。
- 禁在页面里写死颜色：颜色只来自主题 token（`var(--accent)` 等）与登记的序号修饰类。
- 禁编造精确数字：没有来源就用量级（"十万级"、"毫秒级"）或区间。
- 禁连续 3 页同版式（版式与指纹两层都会被服务端打回）。

## 密度

- 每页可见文字 100-220 字（code 页另计，代码 6-14 行）；低于下限会被写入门禁直接拒收。
- 卡片/行说明 18-45 字：完整句，句号结尾。
- **每页要有下半区**：量测会检查填充率，内容只占画布一半不到的页会被打回。
- **数字纪律**：关键数字/对比一律 feature-grid（指标特性）或 cards-3（对照）呈现，不准埋进句子里。

## 节奏

- cover → agenda → …内容… → demo-close 的骨架顺序保持完整。
- cards-3 / feature-grid / rule-list 穿插排，不要连排；10 页以上的 deck 中途至少安排一次 rule-list 或 feature-grid 换节奏。
