# hermes-terminal · 质量规则（生成阶段注入）

本文件是这份模板的专属质量规则，与 layouts.md 的版式锁配合使用。

## 字体与语言

- 全局等宽字体（JetBrains Mono）是模板身份：标题、正文、数字全部照排，不要给中文另引字体，也不要用衬线。
- prompt 行（`hc-prompt`）是叙事钩子：每页开头用一条命令/取值动作点题（`cat xxx`、`echo $X`、`whoami`），命令要像真的，不要编不存在的 flag。
- chrome 标题栏与 footer 眉标用小写英文 + `·` 分隔（如 `benchmark · n=48`），大写转换由 CSS 处理。

## 代码与 trace 纪律（codebox）

- trace / 命令：trace 版式 8-16 行，install 版式 4-10 行；每行 ≤70 字符。
- 语法着色只用登记的类：`cm`（注释）`fn`（阶段/函数）`st`（字符串/结果）`kw`（关键字/提示符）`hl`（diff/高亮）`var`（变量）。不要发明其他着色类。
- 代码必须真实可读——trace 要像真实会话的节选，命令要能直接粘贴执行；写不确定的 API 不如写概念。
- HTML 转义：代码里的 `<`、`>`、`&` 必须写成 `&lt;` `&gt;` `&amp;`。

## 数据纪律

- 数字必须有口径：几次平均、什么条件、样本量多少，写在 `hc-lede` 或卡内 `desc`；没有来源就用量级（"毫秒级"、"十万级"）。
- 关键数字一律走 spec-cards（指标卡）、verdict（大分数）或 compare-chart（柱状图），不准埋进句子里。
- compare-chart 的柱高按 骨架注释 的换算写（高度 = 百分比 × 2.8），顶标数值、底标指标名，图例不许省。

## 禁令

- 禁 emoji（包括 ✅❌🔥✦）：立场用 `hc-tag red`、`verdict -` 这类文字分级表达。
- 禁在页面里写死颜色：颜色只来自主题 token（`var(--hc-green)` 等）。唯一例外：SVG 图表的轴/文字灰 `#8a8892` 与骨架里已写明的 style。
- 禁编造评测结论：说"实测"就要有数据支撑；没测过的写"未测/待验证"，不要装。
- 禁每页都是 trace：代码页与数据页穿插，连续 3 页同版式会被节奏校验打回。
- 禁删空气层：`hc-grid` / `hc-scanlines` / `hc-chrome` / `hc-footer` 是模板身份，每页保留。

## 密度

- 每页可见文字 80-200 字（trace/命令页另计，代码 8-16 行）；低于下限会被写入门禁直接拒收。
- 卡片说明 12-40 字：一句论断 + 一句展开，句号结尾的完整句，不写半截句。
- **每页要有下半区**：量测会检查填充率，内容只占画布一半不到的页会被打回。
- **数字纪律**：关键数字/对比一律 spec-cards、verdict、compare-chart 呈现，不准埋进句子里。

## 节奏

- divider（章节幕）至少在 10 页以上的 deck 出现 1 次；
- 数据页（spec-cards / verdict / compare-chart）与代码页（trace / install）穿插在内容页之间，不要连排；
- cover → divider → …实测… → verdict → thanks 的骨架顺序保持完整。
