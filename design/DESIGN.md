# Deck Agent 前端设计规则

> **配色已定稿（2026-09-16）**：暗色 = 曜石基调 + 青碧主色；亮色 = 冷灰白 + 深青碧。
> 定稿值见 `frontend/src/theme/tokens.css`（唯一权威来源），对比度核验脚本 `tmp/check-contrast.mjs`
> （明暗 22 项配对全部 ≥ WCAG AA 4.5:1）。定稿相对 demo 初版的 4 处 AA 修正：
> 亮色主色 #0D9488→#0F766E、亮色弱化文本 #8B99B3→#5E6E89、亮色成功色 #059669→#047857、
> 暗色弱化文本 #7A7D80→#82868C。其余候选基调/主色（石墨/蓝黑/暖炭/纯黑、靛蓝/湖蓝/赤红）
> 仅为讨论期对照物，不进入实现。

> 从 [taste-skill](https://github.com/…)（反 AI 味前端 skill）中裁剪出的**适用于本项目**的子集。
> 该 skill 明确定位为 landing page / 作品集工具，把"dashboard / 密集产品 UI"划为 out of scope；
> 我们的工作台是产品 UI，所以它的营销页机器（hero 规则 / bento 节奏 / marquee / 滚动编排 / 图片策略）**不采纳**，
> 采纳的是它的跨场景设计纪律。本文件是前端实现的硬约束，评审以此为准。

## 1. 色彩纪律

- **全应用只有一个主色（accent）**，一旦选定，所有页面、所有状态统一使用；不允许"这一块换个颜色点缀"。
- 主色饱和度上限 **80%**（HSL S 值），但**用户明确指定参照的品牌系统例外**（如 Raycast：交互蓝 #55B3FF、
  品牌红 #FF6363 饱和度 100%——参照即品牌授权，保持原值保真）。
- **禁 AI 紫默认**：不出现紫色渐变、紫色按钮辉光；品牌真要紫另说（我们没有）。
- 中性色**一个温度走到底**：暗色基调选定一档后，不允许冷暖灰混用。
- 状态色（success/warning/danger/info）是语义 token，不是装饰色，只用于表达真实状态。
- 阴影必须**染成底色的色相**，禁止纯黑阴影投在亮底上（tokens 里已按此实现）。

### 1.1 暗色基调：曜石（参照 Raycast，用户指定）

暗色默认基调按 Raycast 设计系统执行，四个签名要素缺一不可：

1. **蓝味近黑底**：`#07080a`，绝不允许纯黑 `#000000`——那点蓝冷调是整个气质的来源；
2. **rgba 白描边**：卡片 `rgba(255,255,255,.06~.1)`，若隐若现但结构必需；
3. **多层内嵌阴影**：次级按钮/键帽带"顶部白高光 + 底部暗压线"（macOS 实体感），
   卡片用双环收边（外环 `rgb(27,28,30)` + 内环 `rgb(7,8,10)`）；
   阴影永远成对出现（外层 + inset），单层平面阴影是错的；
4. **正字距**：正文 `letter-spacing: +0.2px`（代码块归零），深底上换取透气感。

配套语义色取 Raycast 系：success `#5FC992`、warning `#FFBC33`、danger `#FF6363`、info/交互 `#55B3FF`。
Raycast 的用法纪律同样采纳：**红是点缀不是主色**（品牌时刻与危险态），蓝才是交互/焦点的颜色；
hover 优先用透明度过渡（~0.85）而非换色。

## 2. 明暗双主题

- 永远**同时设计、同时验证两个主题**，只看过一边不算完成（demo 页的开关就是为此服务的）。
- 禁纯黑 `#000000`、禁纯白 `#ffffff` 作为大面积底/文本极值：暗色用近黑（石墨 #141517 一档）与近白（#E9EBEE），
  亮色文本用 #1B2537 不用纯黑。
- 层级关系两个主题必须**对等**：亮色下主按钮最抢眼，暗色下也必须最抢眼。
- 跟随系统 `prefers-color-scheme` 为默认，手动切换覆盖并存 localStorage。
- **主题锁**：应用外壳整页一个主题，不允许某个区块自己翻转到另一主题。
  唯一例外是**内容画布**：预览区里的 deck.html 用 deck 自己的主题（它是要被导出的作品，不是界面），
  深色外壳衬亮色片子是有意为之的对比策略。

## 3. 形状一致性锁

- 全应用一个圆角体系，当前规则：**控件 8px、卡片/面板 10–12px、胶囊(chip/badge) 全圆、slide 缩略图 8px**。
- 不允许出现游离于体系外的圆角值；要改全局一起改。

## 4. 图标与符号

- **单一图标家族：Phosphor**（`@phosphor-icons/vue`，官方 Vue 包）。
  原定 lucide 作废——taste-skill 明确不推荐（lucide 是 LLM 默认 pick，属于"AI 味"信号之一）。
- 全应用统一 stroke/weight 口径（Phosphor 用 regular 一档，选中态可用 fill 档，不混 duotone）。
- **禁止手绘 SVG 图标路径**；缺图标就换官方字形或组合，不要自己画。
- **禁止 emoji 出现在界面文本和按钮里**（☀ ⚠ ✔ 这类一并禁止），一律用图标组件。
- 间隔点 `·` 每行最多 1 个；破折号（——/—）不作为界面文案元素。

## 5. 交互状态完整性

每个可交互组件必须设计完整状态循环，缺一个就不算做完：

- **加载**：骨架屏（形状对齐最终布局），禁用孤立转圈 spinner；SSE 流式期间的工具卡片本身就是过程态。
- **空态**：说清"这里会有什么 + 怎么让它出现"（如 deck 列表空态给"新建第一份"按钮）。
- **错误**：表单内联在字段下方；toast 只用于瞬态通知。区分"用户的待办"和"服务故障"两类文案（沿用后端约定）。
- **按压**：`:active` 必须有触感反馈（translateY(1px) + scale(.98)），hover 不够。
- **对比度**：按钮文字/背景、表单 placeholder/焦点环/错误文字全部 **WCAG AA（4.5:1）**起；
  双主题各自验证。demo 里的暗色主色用 400 系、亮色用 600 系就是这个原因。
- 禁 placeholder 当 label 用：**设置/登录等表单一律 label 在输入框上方**。
  豁免：对话输入框是命令行式单输入（业界惯例即 placeholder 提示），不适用表单规则。

## 6. 文案纪律

- 不用"赋能/无缝/极致/下一代"这类空洞词；说具体动作。
- 不伪造精确数据（"92%""4.1×"），演示数据要么来自真实接口，要么明确标注 mock。
- 界面文案完成时通读一遍：语法完整、指代清楚、删掉自我陶醉式的俏皮话。无聊但清楚的文案好过聪明但费解的文案。

## 7. 布局与密度（产品 UI 版）

- 表单类布局 label 在上、helper 可选、错误在下，输入块 `gap: 8px`。
- 长列表（>5 项）不许默认"一行一条分割线"糊完：分组、卡片网格、或按需分页。
  （对话消息流、trace 事件时间线是时间序数据，按序排列本身即正确形态，不受此条约束。）
- 卡片只在"高度真的表达层级"时用；能用留白和分割线分组的不套卡片。
- 移动端（窄屏降级）：工作台切"对话/预览"双 tab；列表单列。每个多栏布局必须写明窄屏行为，不接受"反正会换行"。

## 8. 动效纪律

- **每个动画必须能说出一句话的理由**（层级引导/叙事顺序/操作反馈/状态迁移），说不出就删。
- 只动 `transform` 和 `opacity`。
- `MOTION_INTENSITY` 产品 UI 默认 2–3：进出场淡入、hover/按压反馈、工具卡片出现即可；无循环装饰动画。
- `prefers-reduced-motion` 下所有动效（含骨架屏 shimmer）退化为静态——非协商项。

## 9. 工程配套

- 组件只允许用语义 token（--bg/--surface/--accent/…），页面代码禁出现裸色值（magic style）。
- z-index 只给系统性分层（粘条/弹层/toast），在 theme 里登记档位，禁止随手 z-50。
- 交付前对明暗两态各截一次图核对（taste-skill 规则：只看过一个模式的页面不许交付）。

## 10. 简版自检清单（每次交付 UI 过一遍）

- [ ] 主色只有一个且全页一致
- [ ] 明暗两态都看过截图，对比度达标
- [ ] 圆角符合体系（8/10–12/全圆）
- [ ] 图标全部来自 Phosphor，无 emoji、无手绘 SVG
- [ ] 按钮/输入有 hover + active + disabled + 加载 + 空 + 错误态
- [ ] 表单 label 在上方，placeholder 不是唯一的字段说明
- [ ] 动效每条都说得出理由，reduced-motion 下退化
- [ ] 无空洞词、无伪造数据、文案通读过
